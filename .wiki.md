# Project Summary
ResQKit is an offline-first first-aid guidance web app that complements 112 by running a guided emergency wizard (location + call status + triage + hazards + kit-based procedures) and generating a deterministic rescuer handoff brief with optional AI polishing and spoken delivery. It also provides curated, source-referenced “risks & regulations” cards, a Safety Profile consented under GDPR, incident review with full local deletion, and an account-backed “My Kits” registry.

# Project Module Description
## Backend (FastAPI)
- Core setup
  - `core/config.py`: environment/config loading.
  - `core/database.py` + Alembic: database connectivity and migrations.
  - `core/auth.py` + dependencies: authentication primitives for user context.
- AIHub integration (server-side only)
  - `routers/resqkit.py`: custom endpoints for kit recognition and brief polishing.
  - `services/resqkit_ai.py`:
    - `recognize_kit`: multimodal kit item recognition from a single camera frame, constrained to a server whitelist; returns a `degraded` flag for manual fallback.
    - `polish_brief`: rewrites an already-composed rescuer brief into a short spoken handover; prohibited from adding facts.
- Domain services
  - `services/incident_records.py`, `services/registered_kits.py`, `services/storage.py`, `services/user.py`, `services/auth.py`: CRUD and business logic behind routers.
- Routers
  - `routers/auth.py`, `routers/health.py`, `routers/incident_records.py`, `routers/registered_kits.py`, `routers/storage.py`, `routers/user.py`, `routers/settings.py`, `routers/aihub.py`, `routers/resqkit.py`.

## Frontend (React)
- App shell and routing
  - `src/App.tsx`: route wiring for the MVP screens.
  - `components/AppShell.tsx`: global 112-not-confirmed banner behavior and consistent layout.
- Emergency flow (end-to-end)
  - `pages/Index.tsx` (S0): “Call 112 before anything else”, starts incident session without requiring login.
  - `pages/Consent.tsx` (S1): disclaimer acknowledgement + optional separate consent for health data storage.
  - `pages/Profile.tsx` (S2): Safety Profile fields; health fields locked unless consent exists.
  - `pages/Emergency.tsx` (S3–S8): emergency wizard stages:
    - context selection, 112 gate + dispatcher script, triage, hazards, kit selection, guided procedures.
  - `components/KitScanner.tsx` (S6): camera-based kit recognition with manual fallback and privacy messaging.
  - `components/ProcedureRunner.tsx` (S8): step-by-step procedure renderer filtered by the selected kit; timestamps completed steps.
  - `pages/Handoff.tsx` (S9): deterministic on-device brief + optional spoken rewrite via backend; share/copy actions.
  - `pages/Review.tsx` (S10/S12): retention choice, optional archive to account, and explicit “delete everything” local erasure.
- Curated knowledge layer (anti-hallucination)
  - `src/lib/knowledge.ts`: curated content packs for contexts, kit item inventory, hazards, procedures, and obligations with pending-gap rendering.
  - `components/SourceNote.tsx`: provenance chips showing which research document each item derives from.
- Client-side data model (local-first)
  - `src/lib/localStore.ts`: consent/profile/incident/settings persistence in localStorage; includes wipe-all control.
  - `src/lib/incidentContext.tsx`: React context for incident session state with offline behavior.
  - `src/lib/brief.ts`: deterministic “rescuer scene brief” composition and dispatcher script builder.
- Supporting screens
  - `pages/Regulations.tsx` (S11): browse/filter regulation cards from the verified content pack + known gaps list.
  - `pages/Kits.tsx` (S12): account-based CRUD for registered kits and missing-item tracking.
  - `pages/Learn.tsx` (S12b): calm-time reading of procedures and kit items using the same curated data.

# File Description Inventory

- `app/backend/services/resqkit_ai.py`: constrained AI service:
  - kit recognition limited to a server whitelist; degrades gracefully with manual fallback
  - brief polishing constrained to not add facts
- `app/frontend/src/lib/knowledge.ts`: curated contexts, hazard taxonomy, kit inventory, procedures, and regulatory obligations with explicit pending gaps.
- `app/frontend/src/lib/localStore.ts`: localStorage schema + wipe-all implementation; consent split for health data.
- `app/frontend/src/lib/incidentContext.tsx`: incident session state manager for offline-first UX.
- `app/frontend/src/lib/brief.ts`: deterministic dispatcher script and rescuer handoff brief builder.
- `app/frontend/src/components/KitScanner.tsx`: camera-to-recognition UI; sends base64 frame to backend; never persists the frame.
- `app/frontend/src/components/ProcedureRunner.tsx`: renders procedure steps from curated data and filters by kit availability (including improvised “without item” alternatives).
- `app/frontend/src/pages/Emergency.tsx`: orchestrates S3–S8 wizard stages and procedure selection/routing.
- `app/frontend/src/pages/Handoff.tsx`: constructs brief locally; optional spoken output from `/api/v1/resqkit/polish_brief`.
- `app/frontend/src/pages/Review.tsx`: retention options, optional archive to account, and explicit local deletion/erasure.
- `app/frontend/src/pages/Regulations.tsx`: curated regulations browsing with anti-hallucination behavior.
- `app/frontend/src/components/SourceNote.tsx`: provenance rendering.
- `app/frontend/src/index.css`, `app/frontend/tailwind.config.ts`: theme tokens and Tailwind wiring (Terracotta & Clay via CSS variables).

# Technology Stack
- Backend: Python FastAPI
- AI integration: self-hosted, open-source models (Ollama) via AIHubService; multimodal recognition and narrative polishing
- Database: SQLAlchemy + Alembic migrations
- Frontend: React + TypeScript
- Styling: Tailwind CSS with custom CSS-variable tokens (Terracotta & Clay)
- Client data: localStorage (local-first), React Router, TanStack Query
- Auth/Storage: backend auth system + account-backed kit/incident persistence (via backend entities)

# Usage
## Backend
- Install dependencies from `app/backend/requirements.txt`
- Configure environment variables for DB (local PostgreSQL) and AIHub (local Ollama)
- Run the backend service with the project’s standard start flow (see backend README)

## Frontend
- Install dependencies from `app/frontend/requirements.txt` or `package.json` (pnpm lock exists in this repo)
- Run the frontend build/start workflow from `app/frontend/README.md`
- Use the app via the configured frontend entry point; emergency flow is available without login, and kits/archiving require sign-in where applicable
